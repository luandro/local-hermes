# Minimizing prompt time / TTFT — LFM3-1.7B + LoRA on llama.cpp b12686, driven by Hermes Agent v0.14.0

Scope: CPU-only, ~4k-token agent prompt (system + tool schemas + short history).
Model native context is **256K** (tri-hybrid: 13 gated short-conv + 5 SWA + 6 global-attn layers), and at 32K it "prefills at least 2.5x faster and decodes at least 1.8x faster" than comparable 2–9B models on edge devices — so prefill is already this model's strength; the goal is to stop wasting it. <https://huggingface.co/LiquidAI/LFM3-1.7B>

## Notes / gotchas specific to this stack

- **`-c` is not a speed knob for a fixed prompt.** Attention/softmax cost grows with the *actual* sequence length (softmax alone is ~18% of a 32k prefill), not with the configured maximum. Dropping `-c` 64000→16384 only saves KV memory; the 4k prefill time is unchanged. Real speedups: `-t`/`-tb` (#6), prefix caching (#3/#4), and a shorter prompt (#7/#8). <https://github.com/ikawrakow/ik_llama.cpp/discussions/25>
- **LFM3 is a hybrid conv/SWA model.** `--cache-reuse` and SWA-checkpoint tricks are model-dependent and can be silently no-ops on recurrent layers (ggerganov, same thread as Qwen3-Next). Verify reuse via the response `timings.cache_n` field before trusting it. <https://github.com/ggml-org/llama.cpp/issues/18497> · <https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md>
- **Measure with `timings`** (`cache_n`, `prompt_n`, `prompt_ms`) — a fast second request may just be a cache hit, not a faster prefill. <https://llamaperf.com/blog/measure-time-to-first-token-local-llm>
- **If the 64K override is ignored** (pre-fix build): patch `agent/model_metadata.py` `MINIMUM_CONTEXT_LENGTH = 64_000` → `32_000`, delete `__pycache__`, restart. <https://github.com/NousResearch/hermes-agent/issues/24140>

## Top 5 to apply now

1. **Pin threads first:** start `llama-server` with `-t <physcores> --threads-batch <physcores>` — the dominant CPU TTFT factor (cold 2571-token prefill 173 s → 186 ms in the cited benchmark). <https://tiffena.me/blog/llm-cpu-only-inference-benchmark-llama.cpp-server-flags/>
2. **Turn on/verify prefix caching:** leave `--cache-prompt` on, add `--cache-reuse 256 -cram 8192`, and confirm warm turns via `timings.cache_n` (expect ≥95% reuse; warm TTFT down ~92–99%). <https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md>
3. **Set `-c 16384` + `model.context_length: 16384`** so Hermes accepts the smaller window and the server allocates less KV — but only after #1/#2, since `-c` itself won't speed the 4k prefill. <https://hermes-agent.nousresearch.com/docs/integrations/providers>
4. **Kill thinking on tool turns:** `agent.reasoning_effort: none` (and/or `--reasoning-budget 0` on the server) so the model emits the tool call / final content immediately. <https://hermes-agent.nousresearch.com/docs/user-guide/configuration>
5. **Shrink the prefix:** trim `SOUL.md`, `MEMORY.md`, `USER.md`, project context files, and disable unused skills/tools — every token removed from the stable prefix is a token not re-prefilled each turn. <https://hermes-agent.nousresearch.com/docs/developer-guide/prompt-assembly>
