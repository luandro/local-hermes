3. **HIGH — E00 reads the usage ledger, but the prompt guard measures the wrong quantity.** The field names match Hermes, and `total_tokens` is retained in the nested `usage` object. For Chat Completions, Hermes subtracts reported cache buckets from `input_tokens` and accumulates that value across responses. An 8,000-token guard can therefore pass a single 10,000-token prompt with 4,000 cached tokens, or fail two 4,100-token uncached hops. Missing or unreadable usage also lets the guard pass. Hermes exports main-loop and auxiliary usage separately, and a provider response can increment the call counter without supplying token counts. Use raw, correlated **per-request prompt totals** for the max-prompt verdict, keep cumulative usage for spend, and mark missing evidence unmeasured. For a shortcut acceptance test, require the expected hook exit reason and corroborate zero inference with correlated backend request counts. The current disk scorer accepts any percentage matching `/`, which an ordinary model answer can also produce. ### R1.5 acceptance

- **Keep tightened whole-request rules as the production baseline.** Char n-gram TF-IDF and LogReg are a reasonable shadow experiment for paraphrases. Compare raw and sigmoid-calibrated scores on grouped data. Calibration can improve probability estimates but gives no safety guarantee, and SGR bounds error among accepted predictions under its sampling assumptions. The proposed write recall instead conditions on write requests. Measure both `P(block | must fall through)` and `P(must fall through | block)`. Include unsupported targets, ambiguous and compound requests, and unrelated tasks in the safety labels. A false fall-through still costs latency and can worsen contention, so measure safe coverage and backend calls avoided. [R1.5 proposal](/home/luandro/Dev/AI/local-hermes/research/decision-models-and-deterministic-shortcuts.md:62) · [Calibration documentation](https://scikit-learn.org/stable/modules/calibration.html) · [Original SGR paper](https://arxiv.org/abs/1705.08500)
- **Replace the 95% accuracy gate with a safety bound and a coverage comparison.** An always-fall-through router scores 95% on a set with 95% fallback cases. Freeze the threshold before final testing, then require a one-sided 95% upper bound of at most 2% on unsafe blocks among must-fall-through cases, plus greater correctly answered coverage than tightened rules at that safety level. Report PT-BR and EN separately. With zero misses, **149 independent must-fall-through examples** are the mathematical minimum for that bound, per slice if claiming it per slice. That is a test floor. For development, start with several hundred human-labelled examples per language and grow from the observed learning curve. Keep prompt families, translations, and synthetic siblings together across splits. Include real prompts, bilingual minimal pairs, and a separately reported challenge set.

**One change before R1.5:** Replace W1’s substring admission with a whole-request allowlist. Require a match to one supported probe and target before blocking, and make the reproduced counterexamples hard fall-through regressions. That gives the classifier a baseline worth beating.
